# 元胞自动机规律模式搜索（CA pattern hunter）

对一条 `B{S}/S{存活}/C{状态数}/N{邻域}` 规则做随机或定点播种，逐代观察，
把每次试验归类到一种吸引子，并按「类型 × 秩序 × 体量」排序，产出
Markdown 报告 + JSON + 可直接并入 `src/data/patterns.json` 的图案片段。

> **本 skill 只负责找规律。** 平台（内核接口、渲染、界面）已经调好，
> 驾驶内核的那套约束全部固化在 `scripts/hunt.js` 里，不需要在此重复描述，
> 也不要为了"顺手改改平台"去动 `src/js/`——真要动平台请另开任务。
> 平台侧的历史结论（内核接口限制、API 陷阱、渲染几何）记在
> `G:/Hash 2D-CAM/.workbuddy/memory/`。

## 1. 跑一次搜索

```bash
VDIR="C:/Users/flyin/.workbuddy/binaries/node/versions"
NODE="$VDIR/$(cat "$VDIR/current")/node.exe"   # current 是纯文本文件，内容就是版本号
S="G:/Hash 2D-CAM/.workbuddy/skills/ca-pattern-hunter"

# 用预设或已保存规则的名字
"$NODE" "$S/scripts/hunt.js" -r life -s 64x64 -n 240 --md life.md

# 自定义规则 + 只看液滴
"$NODE" "$S/scripts/hunt.js" -r "B2/S34/C2/N123457" -m droplet -d 0.1,0.2,0.4

# 把内置图案丢进任意规则，看它变成什么
"$NODE" "$S/scripts/hunt.js" -r 火雨 --from-pattern glider -g 200

# 导出可并入 patterns.json 的片段
"$NODE" "$S/scripts/hunt.js" -r 蚁穴 -n 400 --emit-pattern found.json
```

`-r` 接受规则字符串，也接受 `presets.json` 的 id/名称与 `saved-rules.json` 的名称
（如 `life`、`highlife`、`火雨`、`蚁穴`）。完整参数见 `hunt.js -h`。

**播种模式**

- `field`：整盘按密度随机。看规则整体的收敛倾向。
- `droplet`：只在中心放 `--droplet` 见方的一小块随机块（默认 8）。找孤立的静物、振荡子、飞船。
- `pattern`：用 `--from-pattern <id>` 把某个内置图案放到中心。**跨规则比较同一图案的首选**。

成本参考：`-n 240 -g 300 -s 64x64` 约 **1.5 秒**。加大 `-n` 比加大 `-g` 更划算。

## 2. 判定逻辑

每次试验逐代取「包围盒 + 以包围盒左上角为原点的稠密副本」，做 **平移不变的规范化**。
于是：签名相同而原点不同 = 平移结构；签名相同且原点相同 = 原地周期。
最终判定必须由 `sameCrop` 逐字节比对确认，哈希只用作查找键。

| 类型 | 判据 | 中文 |
| --- | --- | --- |
| `still` | `crop(t) == crop(t−1)` 且原点不动 | 静物 |
| `oscillator` | `crop(t) == crop(t−p)`，`2 ≤ p ≤ periodMax`，原点不动 | 振荡子 |
| `translator` | `crop(t) == crop(t−p)`，原点平移 `(dx,dy) ≠ (0,0)` | 平移结构（飞船） |
| `died` | 某一代存活数归零 | 消亡 |
| `expanding` | 未命中周期，且末 24 代包围盒尺寸单调不减、相对窗口最小值长了 ≥ 3 | 持续扩张 |
| `chaotic` | 以上都不是 | 混沌 |

两个防伪机制：

- **环绕守卫**：位移超过半个棋盘的命中直接丢弃，避免把环面上的绕行当成飞船。
- **退化守卫**：把位移在包围盒内取模，若取模后非零且裁剪块在该位移下不变，
  说明这块图样自身就有这个平移对称，多半是行波而非飞船。标记为退化，得分乘 0.55。

## 3. 排序口径

```
得分 = 类型权重 × (0.30 + 0.30 × 秩序 + 0.40 × 体量) × 周期项
```

- 类型权重：平移结构 1.0、振荡子 0.9、静物 0.5、扩张 0.45、混沌 0.2、消亡 0.1
- 秩序 =（压缩率、4×4 块序、水平邻接一致）三项算术平均
- 体量 = `min(1, 吸引子存活数 / 40)`
- 周期项：振荡子取 `min(1.15, 0.8 + 0.06 × 周期)`，其余为 1

**体量项是必需的**：三格闪烁器的秩序接近满分（压缩率 0.99），不加体量会霸榜，
把真正有内容的发现挤下去。这是实测踩出来的，不是理论推导。

## 4. 判读须知（必须一起交给用户）

1. 类型是**有限预算内的观察结果**，不是证明。`-g` 之内没命中周期就归入混沌或扩张，加长观察可能改判。
2. 三个秩序项都是启发式代理：压缩率对稀疏图样天然偏高；块序把 4×4 块当独立样本；邻接一致只看水平相邻。它们用于排序，**不是熵率**。
3. 默认边界 `open`（界外读作 0），避免环绕造成的假周期。要复现界面默认的环面要显式传 `--boundary cycle`。
4. `接触边界 = 是` 的命中，形态受边界条件影响，不能当作规则的内禀性质。
5. **平移结构只有在整盘一起平移时才会被识别**。盘面上若同时有飞出去的飞船和不动的碎片，
   整盘签名不再重复，该次试验会落到混沌或静物——这是当前实现的已知盲区。
   要找飞船：小液滴、低密度、大网格，或 `--from-pattern`。
6. 该工具描述的是**规则的吸引子统计**，不是「这条规则好不好玩」。60% 振荡子既可能意味着规则丰富，也可能意味着它单调。

## 5. 结果回灌界面

`--emit-pattern` 写出的数组可直接并入 `src/data/patterns.json`：
每项是 `{id, name, align:'center', rows, rule}`，`rows` 用 `O` 表示活、`.` 表示死、
`B..Z` 表示状态 2..27（与 `ca.js` 的 `cellsOf` 一致），`rule` 是该图案适用的规则代码。
界面只在 `rule` 与当前规则一致时才会把它列进图案下拉。

并入后刷新页面即可，`patterns.json` 是每次打开都重新读的，不进浏览器缓存。

## 6. 自检

改过判定管线之后跑一次（`$NODE` / `$S` 沿用 §1 的定义）：

```bash
"$NODE" "$S/scripts/hunt.js" -r life -s 64x64 --from-pattern glider -g 120
```

期望：唯一命中为「平移结构，周期 4，每周期位移 (1,1)」，吸引子存活 5。
生命游戏滑翔机的理论值就是每 4 代斜移 1 格；对不上说明规范化或周期判定坏了。
